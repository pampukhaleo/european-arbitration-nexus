# Заголовок для главной страницы https://chea-taic.be/

## В чём дело

Ошибка касается ровно одной страницы — корневого адреса без языка (`https://chea-taic.be/`).
Эта страница только перенаправляет посетителя на нужный язык (`/en`, `/fr`, `/ru`), и при сборке
сайта она получается полностью пустой: без заголовка, описания и канонической ссылки.
Все языковые страницы (`/en`, `/fr`, `/ru` и остальные) свои заголовки имеют — проблема
только у корня. Да, это исправимо.

## Что сделаю

Корневая страница перестанет быть пустой:

- у неё появится заголовок и описание (английские, как у главной `/en`);
- каноническая ссылка будет указывать на `https://chea-taic.be/en`, чтобы поисковик считал
  английскую главную основной версией;
- добавятся языковые ссылки-соответствия (en / fr / ru + `x-default`);
- на самой странице появится короткий видимый заголовок и ссылки на три языковые версии —
  чтобы страница не была пустой для роботов, которые не выполняют скрипты.

Перенаправление на язык посетителя работает как раньше, для живого пользователя ничего
не изменится: он по-прежнему мгновенно попадает на свою версию сайта.

## Технические детали

- `src/App.tsx`: компонент `RootRedirect` при серверной генерации (`typeof window === 'undefined'`)
  возвращает не `null`, а разметку с `<Seo>` (title/description из `seoMetadata` для `/`, `lang="en"`,
  canonical `/en`) плюс `<h1>` и три ссылки на `/en`, `/fr`, `/ru`. В браузере поведение прежнее —
  `<Navigate to={'/' + target} replace />`, но с тем же `<Seo>` в разметке до редиректа.
- При необходимости `src/components/Seo.tsx` получит поддержку явного canonical/hreflang для корня
  (проверю текущую реализацию и добавлю проп, только если его ещё нет).
- Сборка `dist/index.html` после этого будет содержать `<title>`, `<meta name="description">`,
  `<link rel="canonical">` и hreflang.
- Sitemap не меняется: корневой URL в нём не нужен, канонический адрес — `/en`.
